# 거짓말 유형 체계 (2판 · 현실판)

`lie_types.json` **하나가 원본**이다. `build.py`가 앱과 웹 페이지를,
`make_docx.py`가 인쇄용 워드를 여기서 생성한다. 유형을 고칠 때는 JSON만 고치면 된다.

```
lie_types.json ──┬─ build.py    → book_analysis_app.html (사이드바 + AI 프롬프트)
                 │              → web/거짓말-도감.html   (멘토 배포용 웹)
                 └─ make_docx.py → 거짓말 12종 도감.docx  (인쇄용)
```

---

## 1. 1판을 왜 버렸나

1판 10종은 **문법 조작 목록**이었다. 확신 올리기, 수량 부풀리기, 화살표 뒤집기,
대상 넓히기 — 문장을 어떻게 손댔는지는 정확했지만, 아이가 살면서 그런 이름으로
거짓말을 만나지 않는다. 교실 밖에서 쓸 데가 없으면 훈련이 아니라 문제 풀이다.

2판은 **어디서 만나는가**를 이름으로 삼았다. 낚시 제목, 조건 숨기기, 권위 빌리기,
건너 들은 말. 유튜브 썸네일과 단톡방과 학원 광고에 실제로 있는 것들이다.
문법적 정확성은 각 유형의 `intext`(글에서의 신호)로 옮겨 두어, 책 요약문을
분석하는 데는 그대로 쓸 수 있게 했다.

## 2. 고르는 순서 — 질문 하나

```
        "이 말이 나한테 무엇을 하려는 거지?"
                       │
   ┌───────────┬───────┴───────┬───────────────┐
크게 보이게    가리려고      원인이라 믿게    남의 말이라며
   1군          2군            3군              4군
 부풀리기   골라 보여주기      엮기          빌리고 얹기
```

각 군에 3개씩. 군을 먼저 정하면 12개 중 고르던 문제가 3개 중 고르는 문제가 된다.

군마다 **의심 신호**가 있어서, 유형을 몰라도 군까지는 갈 수 있다.

| 군 | 하려는 것 | 이럴 때 의심한다 |
| --- | --- | --- |
| 1 · 부풀리기 | 실제보다 크게 보이게 한다 | 말이 실제보다 세게 들린다 |
| 2 · 골라 보여주기 | 있는 것 중 유리한 것만 꺼낸다 | 말한 건 다 사실인데 뭔가 허전하다 |
| 3 · 엮기 | 상관없는 것을 원인처럼 붙인다 | “그래서 그렇게 됐다”가 너무 매끄럽다 |
| 4 · 빌리고 얹기 | 남의 입을 빌리거나 없던 말을 얹는다 | 말한 사람이 누구인지 끝까지 안 나온다 |

## 3. 12종

| # | 유형 | 어디서 만나나 | 되받아치는 질문 |
| --- | --- | --- | --- |
| ① | 낚시 제목 | 유튜브 썸네일, 기사 제목 | 제목이 말한 걸 본문이 정말로 말하고 있나? |
| ② | 최고라고 말하기 | 학원 광고, 상세페이지 | 무엇과 비교해서? 그건 누가 정했지? |
| ③ | 숫자로 꼬시기 | 광고 배너, 건강 정보 | 몇 명 중에 몇 명이지? 누가 세었지? |
| ④ | 성공한 사람만 보여주기 | 합격증 벽, 쇼핑몰 후기 | 안 된 사람은 어디 갔지? |
| ⑤ | 조건 숨기기 | 작은 글씨 약관, 이벤트 배너 | 언제까지, 누구한테, 어떤 경우에만? |
| ⑥ | 불리한 항목 빼기 | 제품 포장 앞면, 변명 | 이것 말고 같이 봐야 할 항목은? |
| ⑦ | 같이 일어난 걸 원인이라 하기 | 건강 기사, 공부법 조언 | 정말 이것 때문일까, 둘 다 딴것 때문일까? |
| ⑧ | 앞뒤 뒤집기 | 혼날 때, 뉴스 해설 | 둘 중 어느 쪽이 먼저 일어났지? |
| ⑨ | 진짜 이유 감추기 | 약속을 어겼을 때, 사과문 | 이 이유가 없어졌다면 결과가 달라졌을까? |
| ⑩ | 권위 빌리기 | 광고 문구, 단톡방 | 그 전문가가 누구지? 다들이 누구지? |
| ⑪ | 건너 들은 말 | 카톡 전달, 소문 | 직접 들은 사람이 누구지? 원래 말은? |
| ⑫ | 없던 결론 얹기 | 기사 공유, 훈계 | 이 결론을 원래 말한 사람이 진짜 말했나? |

각 유형은 JSON에 이렇게 들어 있다.

| 필드 | 쓰임 |
| --- | --- |
| `where` | 현실에서 만나는 자리 3곳 (사이드바 칩) |
| `said` / `actual` | 현실 예시 대조 — 이렇게 말한다 / 실제로는 |
| `why` | 왜 속는지, 심리 |
| `ask` | **되받아치는 질문** — 아이가 실제로 던질 한 문장 |
| `intext` | 책 요약문에서는 어떤 모습으로 나타나는지 |
| `make` | AI가 거짓말을 만들 때의 지침 |
| `vs` | 헷갈리는 유형과의 구분선 |

`ask`가 이 도감의 핵심이다. 유형 이름을 외우는 게 목적이 아니라,
그 자리에서 던질 질문 하나를 갖는 게 목적이다.

## 4. 출제 규칙 (프롬프트에 그대로 들어간다)

1. 거짓말은 정확히 3개, **서로 다른 군에서 하나씩**. 같은 군 중복 금지.
2. 한 문장에서 손대는 건 **딱 한 군데**. 문장 전체를 반대로 만들지 않는다.
3. 바꾸지 않은 부분은 분석에 나온 표현 그대로. 새 단어·새 개념 등장 금지.
4. 극단 단어(모든/항상/절대/전혀) 금지. ③도 “대체로/자주/흔히”까지만.
5. 거짓 문장은 참 문장과 길이·문체·어미가 구별되지 않아야 한다.
6. **미끼 장치**: 참 문장 최소 2개에 “~일 수 있다”, “~할 때”, “~보다”를 남긴다.
   이게 없으면 학생이 “조심스러운 표현이 없는 문장 = 거짓말”이라는 요령만으로 다 찍는다.
7. 거짓말의 원래 내용은 분석 안에 실제로 있어야 한다.
8. 힌트 3단계 — 무엇을 대조할지 / 위치 범위 / 스스로 던질 질문.
9. 요약 문장 2~3개는 세포 이야기를 빌려 쓴 문장으로 만든다. 세포 이야기도 검증 대상이다.
10. **`real` 필드**: 같은 수법을 현실에서 마주치는 장면을 한 문장 쓴다.
    도감 예시를 베끼지 말고 그 책 내용에 어울리는 새 장면을 만든다.
    책 안에서만 끝나면 훈련이 되지 않는다.

앱은 응답을 `lieSetIsValid()`로 검사한다 — 3개인지, 세 군이 모두 다른지,
`idx`가 문장 범위 안인지. 어긋나면 한 번 더 요청한다.
