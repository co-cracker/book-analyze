# 거짓말 유형 체계 (3판)

`lie_types.json` **하나가 원본**이다. `build.py`가 앱과 웹 페이지를,
`make_docx.py`가 인쇄용 워드를 여기서 생성한다. 유형을 고칠 때는 JSON만 고치면 된다.

```
lie_types.json ──┬─ build.py    → book_analysis_app.html (사이드바 + AI 프롬프트)
                 │              → web/거짓말-도감.html   (멘토 배포용 웹)
                 └─ make_docx.py → 거짓말 12종 도감.docx  (인쇄용)
```

---

## 1. 세 번 고친 이유

**1판**은 문법 조작 목록이었다. 정확했지만 이름이 추상적이라 교실 밖에서 쓸 데가 없었다.

**2판**은 현실에서 만나는 자리를 이름으로 삼았다. 이름은 살아났는데, 항목이
유형마다 들쭉날쭉해서 **비교가 안 됐다**. 어떤 건 정의가 길고 어떤 건 예시가 없었다.
고르는 근거가 흐려지니 다시 엉성해졌다.

**3판**은 둘을 합쳤다. 이름과 예시는 현실에서 가져오되, **모든 유형이 똑같은 일곱
칸을 같은 순서로 채운다**. 칸이 같아야 유형끼리 나란히 놓고 비교할 수 있다.

| 칸 | 무엇을 적나 |
| --- | --- |
| `def` 정의 | 무엇을 무엇으로 바꾸는지 한 문장 |
| `spot` 알아보는 법 | 본문의 무엇과 정리의 무엇을 대조하는지, 구체적 절차 |
| `whyLie` 왜 거짓인가 | 이걸 놓치면 무엇을 잘못 믿게 되는지 |
| `bookAuthor` → `bookSummary` | 작가가 쓴 문장 → 정리에 실린 문장 |
| `realSaid` → `realActual` | 현실에서 이렇게 말한다 → 실제로는 |
| `ask` 되받아치는 질문 | 그 자리에서 던질 한 문장 |
| `vs` 헷갈리지 않기 | 가장 가까운 유형과 가르는 기준 |

`bookAuthor` → `bookSummary` 쌍이 규칙성의 핵심이다. 두 문장을 나란히 놓으면
무엇이 바뀌었는지 눈으로 보이고, 설명이 길어질 이유가 없어진다.

## 2. 고르는 순서 — 질문 하나

```
         "이 문장이 본문의 무엇을 건드렸나?"
                       │
   ┌───────────┬───────┴───────┬───────────────┐
  말의 세기    있던 것을 뺌    원인과 이유     주인·없던 말
   1군          2군            3군              4군
 부풀리기   골라 보여주기      엮기          옮기고 얹기
```

각 군에 3개씩. 군을 먼저 정하면 12개 중 고르던 문제가 3개 중 고르는 문제가 된다.

군마다 **의심 신호**가 있어서, 유형을 몰라도 군까지는 갈 수 있다.

| 군 | 건드리는 것 | 이럴 때 의심한다 |
| --- | --- | --- |
| 1 · 부풀리기 | 말의 세기를 한 단계 올린다 | 정리가 본문보다 세게 들린다 |
| 2 · 골라 보여주기 | 있는 것 중 유리한 것만 남긴다 | 말한 건 다 사실인데 뭔가 허전하다 |
| 3 · 엮기 | 원인과 이유를 손댄다 | “그래서 그렇게 됐다”가 너무 매끄럽다 |
| 4 · 옮기고 얹기 | 주인을 바꾸거나 없던 말을 붙인다 | 누구 이야기인지, 누가 한 말인지가 흐릿하다 |

## 3. 12종

| # | 유형 | 작가 → 정리 | 되받아치는 질문 |
| --- | --- | --- | --- |
| ① | 확신 올리기 | "요인일 수 있다" → "요인이다" | 본문이 정말 그렇게까지 말했나? |
| ② | 수량 부풀리기 | "중 일부는" → "대체로" | 몇 명 중에 몇 명이지? |
| ③ | 비교 대상 지우기 | "3번 유형보다 세밀하게" → "세밀하게" | 무엇과 비교해서? |
| ④ | 조건 제거 | "커질 때 물러난다" → "물러난다" | 어떤 경우에만 해당하지? |
| ⑤ | 반례 무시 | "회복으로 이어지지만 고립이 되기도" → "회복으로 이어진다" | 반대쪽 이야기는 어디 갔지? |
| ⑥ | 불리한 항목 빼기 | "창의성을 높이지만 오해를 부른다" → "창의성을 높인다" | 같이 봐야 할 항목은? |
| ⑦ | 상관-인과 둔갑 | "함께 관찰된다" → "만들어 낸다" | 정말 이것 때문일까? |
| ⑧ | 인과 뒤집기 | "결핍감 때문에 집착" → "집착 때문에 결핍감" | 어느 쪽이 먼저 일어났지? |
| ⑨ | 근거 바꿔치기 | "정체성이 흔들리기 때문" → "앞서고 싶기 때문" | 이 이유가 없어도 결과가 같았을까? |
| ⑩ | 주체 바꾸기 | "알아봐 주기를 기다린다" → "먼저 알아봐 주려 한다" | 이 일을 하는 사람이 누구지? |
| ⑪ | 범위 이동 | "4번 유형은" → "사람은" | 원래 누구에 대한 이야기였지? |
| ⑫ | 결론 비약 | (본문에 없음) → "그러므로 극복해야 성숙해진다" | 원래 사람이 진짜 그렇게 말했나? |

각 유형에는 현실에서 만나는 자리와 예시가 함께 붙는다. ①이면 유튜브 썸네일,
④면 작은 글씨 약관, ⑧이면 혼날 때 듣는 말. 책에서 배운 것을 그 자리에서
쓰라고 붙여 둔 것이다.

위 일곱 칸에 더해 `make`(AI가 거짓말을 만들 때의 지침)와 `where`(현실에서
만나는 자리 3곳)가 들어간다. `make`는 화면에 안 보이고 프롬프트에만 실린다.

`ask`가 이 도감의 목적이다. 유형 이름을 외우는 게 아니라, 그 자리에서 던질
질문 하나를 갖는 것이다.

## 4. 출제 규칙 (프롬프트에 그대로 들어간다)

1. 거짓말은 정확히 3개, **서로 다른 군에서 하나씩**. 같은 군 중복 금지.
2. 한 문장에서 손대는 건 **딱 한 군데**. 문장 전체를 반대로 만들지 않는다.
3. 바꾸지 않은 부분은 분석에 나온 표현 그대로. 새 단어·새 개념 등장 금지.
4. 극단 단어(모든/항상/절대/전혀) 금지. ②도 “대체로/자주/흔히”까지만.
5. 거짓 문장은 참 문장과 길이·문체·어미가 구별되지 않아야 한다.
6. **미끼 장치**: 참 문장 최소 2개에 “~일 수 있다”, “~할 때”, “~보다”를 남긴다.
   이게 없으면 학생이 “조심스러운 표현이 없는 문장 = 거짓말”이라는 요령만으로 다 찍는다.
7. 거짓말의 원래 내용은 분석 안에 실제로 있어야 한다.
8. 힌트 3단계 — 무엇을 대조할지 / 위치 범위 / 스스로 던질 질문.
9. 요약 문장 2~3개는 세포 이야기를 빌려 쓴 문장으로 만든다. 세포 이야기도 검증 대상이다.
10. **`real` 필드**: 같은 수법을 현실에서 마주치는 장면을 한 문장 쓴다.
    도감 예시를 베끼지 말고 그 책 내용에 어울리는 새 장면을 만든다.
    책 안에서만 끝나면 훈련이 되지 않는다.

앱은 응답을 `lieSetIsValid()`로 검사한다 — 3개인지, 세 군이 모두 다른지,
`idx`가 문장 범위 안인지. 어긋나면 한 번 더 요청한다.
